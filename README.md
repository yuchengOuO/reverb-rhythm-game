# 殘響 REVERB

一個從零開始的四軌下落式音樂遊戲（Godot 4.7），主打兩個「一般音遊不會做」的機制：

1. **軌道會動** — 四條軌道可以各自平移、旋轉、縮放，音符跟著軌道一起被帶走。
2. **視窗就是玩法** — 譜面可以移動、縮小、震動真實視窗，甚至把遊戲畫面**分割到兩個 OS 視窗**上。

視覺主題是 **「接住白光」**：純黑背景上只有白色光球往下掉，四軌沒有任何顏色差異，
每一軌底部有一顆半透明的玻璃球把光接住。畫面上唯一的顏色是 MISS 的紅。

外加：可自由改鍵、粒子特效、以及一個**獨立的網頁譜面編輯器**（含 BPM 分析）。

---

## 1. 快速開始

1. 用 Godot 4.7 開啟 `project.godot`（雙擊或「匯入」）。
2. 按 `F5` 執行。
3. 主選單 →「開始遊玩」就會列出 `assets/charts/` 裡的所有譜面。

預設鍵位：`D` `F` `J` `K`（可在「設定」裡改成任何鍵）。

> **注意：音檔不在這個 repo 裡。**
> 為了尊重版權（和檔案大小），`assets/audio/` 底下的音樂檔不進 Git。
> clone 之後請自己把音檔放進去，檔名要跟譜面 `meta.audio` 寫的一致，做法見下一節。

---

## 2. 放音樂

把 `.mp3` / `.ogg` / `.wav` 丟進：

```
assets/audio/
```

（放在這個資料夾裡的音檔**不會**被 Git 追蹤，也不會出現在 GitHub 上。）

然後在譜面的 `meta.audio` 填路徑，例如：

```json
"audio": "res://assets/audio/my_song.mp3"
```

也可以只寫檔名 `"my_song.mp3"`，遊戲會自動到 `assets/audio/` 找。
**最省事的做法就是只寫檔名**，之後整包資料夾搬走也不會壞。

**不支援 `.m4a` / `.aac`**（Godot 原生不支援）。先轉檔：

```bash
ffmpeg -i "song.m4a" -b:a 192k "song.mp3"
```

### 加一首新歌的完整流程

1. 把音檔放進 `assets/audio/`（例如 `my_song.mp3`）。
2. 打開 `tools/chart_editor.html`。
3. 按「載入音樂」選同一個檔案 → 按「BPM 分析」抓 BPM 與第一拍偏移。
4. 在鋼琴卷軸上點出音符（左鍵新增、拖曳可拉長按）。
5. 按「匯出譜面」，存到 `assets/charts/my_song.json`。
6. 回到遊戲 →「開始遊玩」，清單裡就會多一首。

> 譜面清單會自動掃描 `assets/charts/*.json` 與 `user://charts/*.json`，
> 所以加新歌只要「丟音檔 + 丟譜面」，不用改程式。

## 2-1. 視覺主題：接住白光

| 元素 | 長什麼樣子 |
|---|---|
| 背景 | 純黑 `#000000`，只有極淡的拍線（alpha 0.013）幫助抓節奏 |
| 音符 | 預設是白色**長條光塊**（中間一條亮芯），可在設定切成**圓形光球**。四軌完全同色，只能靠位置判斷軌道 |
| 長按 | 一道從判定球往上延伸的**光柱**，中心亮白、兩側收暗，尾端是一小段光帽 |
| 判定點 | 半透明的**玻璃球**，內部幾乎全黑、靠邊緣一圈白光撐出球體形狀；球心有一點微光，接到光時會亮成熱點 |
| 判定基準 | 穿過球心的極淡水平線（赤道線）。音符中心對齊這條線的瞬間就是判定點 |
| 打擊回饋 | 球體亮起 + 一道白光向兩側擴散 + 白色粒子爆散 |
| 唯一顏色 | MISS 的紅 `#ff4d57`，其餘全部是白與灰 |

**音符樣式**在「設定 → 音符樣式」切換（長條 / 圓球，預設長條），
選擇會存進 `user://settings.cfg`。開發時也可以臨時指定：

```bash
godot --path . -- --autoplay --note=orb
```

要改回四軌分色，只需要改 `game/Playfield.gd` 的 `LANE_COLORS` 陣列（現在四格都是白色）。
尺寸在 `_layout()`：`note_r`（圓球半徑）、`note_bar_w` / `note_bar_h`（長條寬高）、`rec_r`（判定球）。

> **軌道重疊時不會互相遮擋**：四條軌道的底色先在這一層全部畫完，音符才畫上去，
> 而且每顆音符外圍有一圈「黑色間隙」（在黑底上看不見），
> 兩顆音符重疊時會露出一道暗縫，後面的音符仍然辨識得出來。

## 4. 兩個特色機制

### 4-1 軌道會動

譜面裡每一軌都有一串「關鍵影格」：

```json
"lanes": [
  { "beat": 32, "lane": 0, "x": -0.55, "rot": -7, "scale": 1.0, "ease": "smooth" }
]
```

* `x` / `y` 的單位是**軌道寬度**（`1.0` = 往右一根軌道），所以視窗大小改變時比例不會跑掉。
* `rot` 是角度，`scale` 是軌道寬度倍率。
* `ease` 支援 `linear` / `smooth` / `in` / `out` / `back` / `step`。

實作上，每一軌是一個 `Transform2D`，音符畫在「軌道本地座標」裡，
所以軌道一轉，上面的音符跟判定點會一起轉 —— 但**判定只看時間與軌道編號**，
畫面再亂，你打的還是同一件事。

### 4-2 視窗就是玩法

```json
"windows": [
  { "beat": 44, "type": "split", "count": 2 },
  { "beat": 50, "type": "merge" }
]
```

支援事件：

| type | 參數 | 效果 |
|---|---|---|
| `move` | `dx`, `dy`（螢幕比例）, `duration` | 移動視窗 |
| `resize` | `w`, `h`（相對倍率）, `duration` | 縮放視窗 |
| `recenter` | `duration` | 把視窗移回目前螢幕的正中央（扣掉工作列） |
| `shake` | `strength`, `duration` | 震動 |
| `split` | `count`（2–3） | 把畫面分割到多個原生視窗 |
| `merge` | — | 合併回來 |
| `ontop` | `on` | 置頂 |
| `borderless` | `on` | 無邊框 |

**原理**：遊戲畫面其實畫在一個 `SubViewport` 裡，主視窗只是「顯示這張貼圖」。
所以分割視窗時，每個視窗只是用 shader 取同一張貼圖的不同 UV 區塊，
遊戲邏輯完全不用知道這件事。

### 分割之後，另一塊視窗怎麼控制？

分割出來的視窗是**真正的 OS 視窗**，但它是無邊框的，沒有標題列可以拖。
所以視窗內部自己做了手勢（`game/SplitWindow.gd`）：

| 操作 | 效果 |
|---|---|
| 在視窗內**按住左鍵拖曳** | 移動這個視窗 |
| **滾輪** | 以視窗中心縮放（放大 = 那一塊畫面跟著放大） |
| **雙擊** | 還原成譜面安排的大小與位置 |
| `Esc`（在遊戲主視窗） | 暫停並強制合併、還原所有視窗 |

視窗右下角會顯示一行提示，4 秒後淡出。

在「設定」裡可以關掉 `允許譜面控制視窗`，關掉後所有視窗事件都會被忽略。

### 4-3 長條（Hold）的判定

長條刻意做得比一般音遊寬鬆，因為這個遊戲的畫面和視窗本身已經夠忙了：

| 規則 | 數值 | 說明 |
|---|---|---|
| 尾端放寬 | `len × 18%`，夾在 0.18–0.40 秒 | 3 秒的長條在 2.6 秒之後放開都算完成 |
| 沒有尾判 | — | 完成時不判 PERFECT/GREAT，只給一點光暈回饋 |
| 中斷緩衝 | 0.14 秒 | 按住期間換指、手滑短暫放開，只要在這時間內按回來就不算斷 |

也就是說：**只有「提早很多放開」才會 MISS**，而那個 MISS 會凍結當下的光柱長度再淡出，
不會讓整條光柱瞬間消失。係數在 `game/Playfield.gd` 開頭：

```gdscript
const HOLD_GRACE_MIN := 0.18
const HOLD_GRACE_MAX := 0.40
const HOLD_GRACE_RATIO := 0.18
const HOLD_REPRESS_BUFFER := 0.14
```

## 5. 譜面編輯器

打開 `tools/chart_editor.html`（直接雙擊，不需要伺服器、不需要安裝）。

### 流程

1. **載入音樂** — 選 mp3 / ogg / wav。
2. **分析 BPM** — 會做頻譜通量 + 梳狀濾波，列出幾個候選 BPM 與 offset，點一下就套用。
   （也可以手動輸入或用 Tap Tempo。）
3. **畫音符** — 左鍵新增、拖曳變長按、右鍵刪除、拖曳音符移動。
4. **做隊形** — 在右邊的「隊形預覽」拖曳軌道，按「在目前拍新增關鍵影格」。
5. **加視窗事件** — 選類型、填參數、按新增。
6. **匯出 JSON** — 存到 `assets/charts/`，遊戲就抓得到。

### 隊形編輯（拖曳 / 微調 / 放大）

| 操作 | 效果 |
|---|---|
| 拖曳軌道 | 左右移動（`x`） |
| `Shift` + 拖曳 | 旋轉（`rot`，±45°） |
| `Alt` + 拖曳 | 縮放（`scale`，0.4–1.8） |
| 點一下軌道 | 選取，下方會出現 X / 旋轉 / 縮放的數值欄位 |
| 方向鍵（已選取軌道時） | ← → 移動 0.01、↑ ↓ 旋轉 1°；按住 `Shift` 加速 |
| 點空白處 | 取消選取（方向鍵恢復成移動播放位置） |
| **放大編輯** | 把預覽畫布放大到整個視窗（`Esc` 或「完成」返回） |
| **重置隊形** | 四軌回到 `x=0, rot=0, scale=1`（再按「新增關鍵影格」寫入） |
| **清空所有關鍵影格** | 清掉整份譜面的隊形（會先詢問） |

**靈敏度**滑桿預設 `0.35×`——舊版固定 `1.0`，滑鼠拉 10 像素軌道就跑掉 10 像素，
很難放到想要的位置。現在拖曳是「以按下瞬間的值為基準」做增量，
不會把每一次 mousemove 的小誤差累積起來，放開時位置跟手是對的。
真的要精準到小數第二位，就用數值欄位或方向鍵。

放大編輯不是另開瀏覽器視窗，而是把同一塊 canvas 搬進全螢幕覆蓋層：
這樣拖曳邏輯、選取狀態、數值欄位都只有一份，不會有兩邊不同步的問題。

### 快捷鍵

| 鍵 | 功能 |
|---|---|
| `空白` | 播放 / 暫停 |
| `1`–`4` | 在目前拍、對應軌道放一個音符 |
| `Delete` | 刪除選取音符 |
| `Ctrl+S` | 匯出 |
| 方向鍵 | 移動播放位置（有選取軌道時改成微調隊形） |
| 滾輪 | 捲動畫面（`Shift` + 滾輪 = 縮放） |

編輯器每 4 秒會自動存一份草稿到瀏覽器的 localStorage，
按上方「還原草稿」可以救回來。

## 6. 譜面格式

```json
{
  "format": "reverb-chart",
  "version": 1,
  "meta": {
    "title": "Untitled (Demo)",
    "artist": "local",
    "difficulty": "Normal",
    "level": 8,
    "audio": "res://assets/audio/my_song.mp3"
  },
  "timing": {
    "offset": 0.375,
    "bpm_segments": [{ "beat": 0, "bpm": 120 }]
  },
  "notes":   [{ "beat": 8.0, "lane": 0, "len": 0.0 }],
  "lanes":   [{ "beat": 32, "lane": 0, "x": -0.55, "rot": -7, "scale": 1.0, "ease": "smooth" }],
  "windows": [{ "beat": 44, "type": "split", "count": 2 }]
}
```

* **音符用「拍」儲存，不是秒。** 改 BPM 或做 BPM 變化時，音符會自動跟著跑。
* `offset`：第 0 拍在音檔中的秒數（前奏長度）。音檔前面有空白就調大。
* `bpm_segments`：支援多段 BPM，段落之間以拍數銜接。
* `len`：長按長度（拍）。`0` = 單點。
* `lanes` 的 `x` / `y` 單位是軌道寬度，不是像素。

## 7. 專案結構

```
project.godot            專案設定（autoload、多視窗、視窗尺寸）
main.tscn                只有一個節點，其餘全部由程式建立
game/
  Settings.gd            Autoload：鍵位、延遲、流速、設定存檔
  Main.gd                流程控制 + 全部 UI
  Chart.gd               譜面資料模型（JSON 讀寫、拍↔秒）
  Conductor.gd           音樂時鐘（預捲、延遲補償）
  Playfield.gd           四軌玩法：繪製、判定、長按、粒子、軌道變換
  WindowDirector.gd      視窗特效：移動、縮放、分割多視窗
  SplitWindow.gd         分割出來的子視窗（拖曳移動 / 滾輪縮放 / 雙擊還原）
  AudioLoader.gd         音樂檔載入（含外部檔案）
assets/
  audio/                 音檔放這裡（*.mp3 / *.ogg / *.wav 不進版控）
  charts/*.json          譜面（進版控，會被自動掃描）
  fonts/NotoSansTC-Regular.otf
tools/
  chart_editor.html      獨立譜面編輯器
```

整個遊戲幾乎沒有 `.tscn`，畫面都是程式即時畫出來的。
好處是「所見即程式碼」，改數值不用開編輯器；壞處是不能用編輯器拉 UI。
如果你想要混合式（部分場景用編輯器做），把 `Playfield` 換成一個 `Node2D` 場景即可。

## 8. 程式架構（想改的話從這裡下手）

### 時間是怎麼算的

`Conductor.gd`：

```gdscript
實際時間 = 播放位置 + 距離上次混音的時間 - 輸出延遲
```

直接拿 `get_playback_position()` 判定會有 10–30ms 的鋸齒，所以要補這兩項。
另外有 2.6 秒的 `preroll`（預捲），這段時間 `song_time` 是負的，音符會先掉下來。

### 判定

`Playfield.gd` 的 `_try_hit()`：

| 判定 | 誤差 |
|---|---|
| PERFECT | ±45 ms |
| GREAT | ±85 ms |
| GOOD | ±135 ms |
| MISS | 超過 180 ms |

想調難度就改這四個常數。

長條（Hold）的頭部用同一套判定，但尾端另外有一套放寬規則（見 4-3），
而且長條是**獨立追蹤**的：`_active_holds` 存的是「正在按住 / 正在淡出」的音符索引，
不是用時間視窗回頭掃描。這一點很重要——用時間視窗掃的話，
按住超過視窗長度之後那顆音符就再也掃不到，光柱會突然消失、判定也永遠不會完成。

### 音符為什麼不是節點

所有音符都只是一筆資料，整個畫面在**一次 `_draw()`** 裡畫完。
好處是幾百顆音符也不會有節點管理的開銷，而且軌道變換只要換一個 `Transform2D`。

### 想加新特效

* 打擊粒子：`Playfield._build_particles()`（`CPUParticles2D`，貼圖是程式產生的）。
* 擴散光波：`_spawn_ring()` / `_draw_rings()`。
* 畫面震動：`_shake`。

### 想改視覺

畫面上所有東西都是 `_draw()` 裡用程式畫出來的，沒有外部圖檔：

| 想改的東西 | 去哪裡找 |
|---|---|
| 光球的長相 | `_draw_orb()`（圓球音符與判定球共用）、`_make_orb_texture()` |
| 長條音符的長相 | `_draw_bar_note()`、`_draw_capsule()`、`_layout()` 的 `note_bar_w` / `note_bar_h` |
| 長按光柱 | `_draw_hold_body()`、`_make_beam_texture()`（橫向漸層） |
| 判定球的尺寸／亮度 | `_draw_receiver()`、`_layout()` 的 `rec_r` |
| 音符光球大小 | `_layout()` 的 `note_r` |
| 柔光貼圖 | `_make_glow_texture()`（徑向漸層，白色） |
| 背景 | `_draw_background()`（純黑 + 拍線 + 底部光池） |
| 四軌是否分色 | `LANE_COLORS` 陣列（現在四格都是 `Color(1,1,1)`） |

## 9. 開發用指令

```bash
# 直接開始第一張譜面
godot --path . -- --autoplay

# 自動完美打擊（驗證判定與計分）
godot --path . -- --autoplay --autohit

# 直接跳到某個畫面（改 UI 時很方便）：menu / select / settings
godot --path . -- --screen=settings

# 臨時切換音符樣式（不寫入設定檔）：bar / orb
godot --path . -- --autoplay --note=orb
```

### 不用開視窗也能驗證判定

`--autohit` 會在音符進入判定視窗時自動按下，跑完後把成績印到 console。
搭配 `--headless` 就能當成回歸測試：只要有漏判，`MISS` 就不是 0。

```bash
# 完整跑一首（2600 幀 ≈ 43 秒）
godot --headless --path . --fixed-fps 60 --quit-after 2600 -- --autoplay --autohit
# 輸出範例：[AUTOTEST] grade=SS score=126214 acc=1.0000 max_combo=260 P=260 G=0 D=0 M=0
```

音符數量取決於載入的譜面（`_default_chart()` 會拿 `assets/charts/` 排序後的第一張），
所以 `P` 的數字會跟著換；重點是 `M=0`、`acc=1.0000`。
換幀率再跑一次應該得到**完全相同**的分數——判定只看歌曲時間，不看幀數：

```bash
for fps in 144 60 30 20 15; do
  godot --headless --path . --fixed-fps $fps --quit-after $((fps*42)) -- --autoplay --autohit
done
```

### 離屏錄影（不開視窗也能看畫面）

```bash
godot --path . --resolution 1280x720 --write-movie out.avi --fixed-fps 30 --quit-after 1200 -- --autoplay --autohit
ffmpeg -ss 11 -i out.avi -frames:v 1 frame.png
```

注意：錄影模式**無法真的改變視窗大小**，所以譜面裡的 `resize` 事件在錄影中
會看起來像「畫面被放大」（遊戲內 viewport 縮小了，但錄影解析度沒變）。
真實視窗下是正常的，錄影時避開那幾拍就好。

## 10. 已知限制 / 下一步

* **多視窗**需要作業系統允許建立子視窗；少數環境（遠端桌面、某些視窗管理器）可能失效。
  失效時遊戲本身仍可玩，按 `Esc` 會還原。
* 分割視窗的縮放是**等比例縮放同一塊裁切畫面**（放大 = 看得更少但更大），
  不是「看到更多遊戲畫面」。要看到更多內容得改 shader 的 `uv_scale`，
  但那樣兩塊視窗的內容會重疊。
* **匯出成執行檔**時，`assets/charts/*.json` 要記得加進匯出篩選條件
  （專案 → 匯出 → 資源 → 篩選 `*.json`），否則選曲列表會是空的。
* 目前沒有：打擊音效、成績上傳、Replay、手把支援、變速（BPM 變化已在格式支援，但示範譜面沒用到）。
* 想要「多軌 + 對手」的話，可以擴充 `Chart` 的 note 欄位（例如加 `side`），
  再讓 `Playfield` 分兩組繪製。
