# 殘響 REVERB

一個從零開始的四軌下落式音樂遊戲（Godot 4.7），主打兩個「一般音遊不會做」的機制：

1. **軌道會動** — 四條軌道可以各自平移、旋轉、縮放，音符跟著軌道一起被帶走。
2. **視窗就是玩法** — 譜面可以移動、縮小、震動真實視窗，甚至把遊戲畫面**分割到兩個 OS 視窗**上。

視覺主題是 **「接住白光」**：純黑背景上只有白色光球往下掉，四軌沒有任何顏色差異，
每一軌底部有一顆半透明的玻璃球把光接住。畫面上唯一的顏色是 MISS 的紅。

外加：可自由改鍵、打擊粒子、**九種全畫面特效**（閃光／故障／反色…），
以及一個**獨立的網頁譜面編輯器**（BPM 分析 + 鼓點／旋律采音輔助）。

---

## 1. 快速開始

1. 用 Godot 4.7 開啟 `project.godot`（雙擊或「匯入」）。
2. 按 `F5` 執行。
3. 主選單 →「開始遊玩」會**直接進上次玩的那首**（按鈕下面會寫是哪一首）；
   要換歌按「選擇譜面」，清單會列出 `assets/charts/` 裡的所有譜面。

預設鍵位：`D` `F` `J` `K`（可在「設定」裡改成任何鍵）。

> **注意：音檔不在這個 repo 裡。**
> 為了尊重版權（和檔案大小），`assets/audio/` 底下的音樂檔不進 Git。
> clone 之後請自己把音檔放進去，檔名要跟譜面 `meta.audio` 寫的一致，做法見下一節。

---

## 2. 放音樂

把 `.mp3` / `.ogg` / `.wav` 丟進：

```
assets/audio/
```

（放在這個資料夾裡的音檔**不會**被 Git 追蹤，也不會出現在 GitHub 上。）

然後在譜面的 `meta.audio` 填路徑，例如：

```json
"audio": "res://assets/audio/my_song.mp3"
```

也可以只寫檔名 `"my_song.mp3"`，遊戲會自動到 `assets/audio/` 找。
**最省事的做法就是只寫檔名**，之後整包資料夾搬走也不會壞。

**不支援 `.m4a` / `.aac`**（Godot 原生不支援）。先轉檔：

```bash
ffmpeg -i "song.m4a" -b:a 192k "song.mp3"
```

### 加一首新歌的完整流程

1. 把音檔放進 `assets/audio/`（例如 `my_song.mp3`）。
2. 打開 `tools/chart_editor.html`。
3. 按「載入音樂」選同一個檔案 → 按「BPM 分析」抓 BPM 與第一拍偏移。
4. 在鋼琴卷軸上點出音符（左鍵新增、拖曳可拉長按）。
5. 按「檢查譜面」確認沒有重複 / 超長，再按「匯出 JSON」，存到 `assets/charts/my_song.json`。
6. 回到遊戲 →「開始遊玩」，清單裡就會多一首。

> 譜面清單會自動掃描 `assets/charts/*.json` 與 `user://charts/*.json`，
> 所以加新歌只要「丟音檔 + 丟譜面」，不用改程式。

## 2-1. 視覺主題：接住白光

| 元素 | 長什麼樣子 |
|---|---|
| 背景 | 預設純黑 `#000000`，只有極淡的拍線（alpha 0.013）幫助抓節奏；譜面可指定背景圖，玩家也能在暫停選單換成自己的照片 |
| 音符 | 預設是白色**長條光塊**（中間一條亮芯），可在設定切成**圓形光球**。四軌完全同色，只能靠位置判斷軌道 |
| 長按 | 一道從判定球往上延伸的**光柱**，中心亮白、兩側收暗，尾端是一小段光帽 |
| 判定點 | 半透明的**玻璃球**，內部幾乎全黑、靠邊緣一圈白光撐出球體形狀；球心有一點微光，接到光時會亮成熱點 |
| 判定基準 | 穿過球心的極淡水平線（赤道線）。音符中心對齊這條線的瞬間就是判定點 |
| 打擊回饋 | 球體亮起 + 一道白光向兩側擴散 + 白色粒子爆散（每次擊中各自獨立，不會蓋掉前一次） |
| 唯一顏色 | MISS 的紅 `#ff4d57`，其餘全部是白與灰 |

**音符樣式**在「設定 → 音符樣式」切換（長條 / 圓球，預設長條），
**音符大小**在下面那條滑桿調（0.60×–1.80×），兩者都會存進 `user://settings.cfg`。
同一頁的**打擊特效**可以關閉擊中粒子，或把粒子數量（0.25×–2.00×）與大小（0.50×–2.00×）調低；
這些設定只影響玩家本機，不會寫進譜面。開發時也可以臨時指定樣式：

```bash
godot --path . -- --autoplay --note=orb
```

音符大小會乘上譜面自己的預設值（見 §6 的 `settings`），
判定球只跟著放大一半——全放大的話四顆球會黏在一起。

要改回四軌分色，只需要改 `game/Playfield.gd` 的 `LANE_COLORS` 陣列（現在四格都是白色）。
基準尺寸在 `_layout()`：`note_r`（圓球半徑）、`note_bar_w` / `note_bar_h`（長條寬高）、`rec_r`（判定球）。

> **連打時打擊粒子不會互相覆蓋**：每一軌有 12 個獨立發射器環狀輪替（`FX_POOL_PER_LANE`），
> 每次擊中優先拿已經跑完的那一顆，前一次的粒子會把 1.4 秒的行程跑完。
> 粒子生命 + 重力（`FX_LIFETIME` / `FX_GRAVITY`）調到會先往上炸開、再掉出畫面下緣，
> 所以不會出現「飛到一半被硬切」的殘影。粒子關閉時連同擊中光環一起省略，低效能裝置只留判定文字。

> **軌道重疊時不會互相遮擋**：四條軌道的底色先在這一層全部畫完，音符才畫上去，
> 而且每顆音符外圍有一圈「黑色間隙」（在黑底上看不見），
> 兩顆音符重疊時會露出一道暗縫，後面的音符仍然辨識得出來。

## 4. 玩法機制

### 4-1 軌道會動

譜面裡每一軌都有一串「關鍵影格」：

```json
"lanes": [
  { "beat": 32, "lane": 0, "x": -0.55, "rot": -7, "scale": 1.0, "ease": "smooth" }
]
```

* `x` / `y` 的單位是**軌道寬度**（`1.0` = 往右一根軌道），所以視窗大小改變時比例不會跑掉。
* `rot` 是角度，`scale` 是軌道寬度倍率。
* `ease` 支援 `linear` / `smooth` / `in` / `out` / `back` / `step`。

實作上，每一軌是一個 `Transform2D`，音符畫在「軌道本地座標」裡，
所以軌道一轉，上面的音符跟判定點會一起轉 —— 但**判定只看時間與軌道編號**，
畫面再亂，你打的還是同一件事。

### 4-2 視窗就是玩法

```json
"windows": [
  { "beat": 44, "type": "split", "axis": "vertical", "move": "mirror" },
  { "beat": 50, "type": "merge" }
]
```

支援事件：

| type | 參數 | 效果 |
|---|---|---|
| `move` | `dx`, `dy`（螢幕比例）, `duration` | 移動視窗 |
| `resize` | `w`, `h`（相對倍率）, `anchor`, `duration` | 縮放視窗。`anchor` 決定哪一角不動：`center`（預設，中心對稱）/ `topleft` / `topright` / `bottomleft` / `bottomright` |
| `recenter` | `duration` | 把視窗移回目前螢幕的正中央（扣掉工作列）。分割中會以**合併後的整體**為準 |
| `shake` | `strength`, `duration` | 震動 |
| `split` | `axis`, `move` | 把畫面分割成**兩塊**原生視窗。`axis` = `vertical`（左右）/ `horizontal`（上下）；`move` = `mirror`（預設，以中線對稱）/ `same`（同方向） |
| `merge` | — | 合併回來 |
| `ontop` | `on` | 置頂 |
| `borderless` | `on` | 無邊框 |

**原理**：遊戲畫面其實畫在一個 `SubViewport` 裡，主視窗只是「顯示這張貼圖」。
所以分割視窗時，每個視窗只是用 shader 取同一張貼圖的不同 UV 區塊，
遊戲邏輯完全不用知道這件事。

### 縮放時，遊戲 UI 不會跟著縮放

`resize` 改變的是**視窗**，不是遊戲畫面。版面（軌道寬度、音符大小、判定線位置、HUD）
在開場時就固定成「這個譜面開場的視窗大小」，之後：

| 視窗變化 | 結果 |
|---|---|
| 變小 | 從四周**裁掉**，音符與判定點比例不變（真的會看不到外圍） |
| 變大 | 四周**露出更多背景**，UI 一樣大、位置不變 |

這是刻意的：如果 UI 跟著縮放，把視窗縮小只會讓畫面變小、資訊一點都沒少，
「視窗就是玩法」就不成立了。

> 實作在 `Playfield.stage_size`（固定版面）與 `view_size`（實際繪圖區），
> 兩者的差除以二就是節點位移，所以 `_draw()` 裡永遠用版面座標。

### 分割成兩塊

`split` 只會分成兩塊，`axis` 決定切的方向：

| `axis` | 兩塊的位置 | 各自看到 |
|---|---|---|
| `vertical`（垂直線） | 左 / 右 | 舞台的左半 / 右半 |
| `horizontal`（水平線） | 上 / 下 | 舞台的上半 / 下半 |

`move` 決定「移動其中一塊時，另一塊怎麼走」：

| `move` | 行為 |
|---|---|
| `mirror`（預設） | 以分割線為鏡射軸，**相反方向**。左塊往右 → 右塊往左，兩塊會靠近或分開 |
| `same` | **相同方向**，兩塊一起平移，維持原本的間距 |

鏡射只反轉「垂直於分割線」的那個軸：垂直分割時只反轉 X，上下仍然一起動；
水平分割時只反轉 Y。這樣兩塊的畫面才不會上下錯位。

移動來源都適用：譜面的 `move` 事件、玩家用標題列拖主視窗、`Alt` + 拖曳、
直接拖分割視窗、滾輪縮放分割視窗。

`merge` 會把主視窗長回原本的大小，並以**兩塊的中心**為準 ——
所以就算兩塊已經被鏡射拉開，合併時也會從中間長回去，而不是從左上角往右下長。

### 分割之後，另一塊視窗怎麼控制？

分割出來的視窗是**真正的 OS 視窗**，但它是無邊框的，沒有標題列可以拖。
所以視窗內部自己做了手勢（`game/SplitWindow.gd`）：

| 操作 | 效果 |
|---|---|
| 在視窗內**按住左鍵拖曳** | 移動這個視窗（主視窗會依 `move` 跟著走） |
| **滾輪** | 以視窗中心縮放（放大 = 那一塊畫面跟著放大） |
| **雙擊** | 還原成譜面安排的大小與位置 |
| `Esc`（在遊戲主視窗） | 暫停並強制合併、還原所有視窗 |

反過來也一樣：玩家用標題列拖主視窗、或 `Alt` + 拖曳時，分割視窗會跟著動。
（實作是每幀比對主視窗的實際位置，所以系統的視窗快捷鍵也吃得到。）

視窗右下角會顯示一行提示，4 秒後淡出。

**譜面控制視窗是遊戲機制，沒有開關可以關掉。**（這是這個遊戲的核心玩法之一。）

### 無邊框模式

譜面可以指定「進場就是無邊框」（`settings.borderless`，預設 `true`）。
無邊框視窗沒有標題列，所以主視窗另外提供了逃生口：

| 操作 | 效果 |
|---|---|
| `Alt` + 左鍵拖曳 | 移動主視窗 |
| `Alt` + 滾輪 | 以畫面中心縮放主視窗 |

分割出來的子視窗不需要 `Alt`——它們本來就接受直接拖曳（見上表）。
`Esc` 暫停會把邊框、大小、位置全部還原。

### 4-2-1 背景（純黑 / 譜面預設 / 自訂照片）

預設是純黑。譜面可以在 `settings.background` 指定一張圖（放在 `assets/backgrounds/`），
玩家也可以在**暫停選單 → 背景**切換：

| 模式 | 顯示 |
|---|---|
| 純黑 | 什麼都不畫（主題原本的樣子） |
| 譜面預設 | 譜面 `settings.background` 指定的圖；譜面沒指定時這個按鈕會隱藏 |
| 自訂照片 | 玩家自己選的圖，會複製到 `user://backgrounds/`，原檔搬走也不會壞。已選過時按一下直接切回，再按「更換照片…」才開檔案選擇 |

* 背景一律以 **cover** 等比填滿整個舞台，不會變形；再壓一層可調的黑幕（`settings.background_dim`，預設 `0.45`），
  避免背景搶走白光的對比。
* 選擇會**按譜面記住**，存在獨立的 `user://backgrounds.json`（key 是譜面路徑的 md5 前 16 碼），
  不會把 `settings.cfg` 撐大。
* 自訂圖讀不到時（換電腦、檔案被刪）會退回譜面預設，不會突然變成全黑。
* 譜面若指定 `settings.window`，進場時會套用一次初始視窗大小／位置；暫停恢復不會再把玩家拖過的視窗拉回去。

### 4-3 長條（Hold）的判定

長條刻意做得比一般音遊寬鬆，因為這個遊戲的畫面和視窗本身已經夠忙了：

| 規則 | 數值 | 說明 |
|---|---|---|
| 尾端放寬 | `len × 18%`，夾在 0.18–0.40 秒 | 3 秒的長條在 2.6 秒之後放開都算完成 |
| 沒有尾判 | — | 完成時不判 PERFECT/GREAT，只給一點光暈回饋 |
| 中斷緩衝 | 0.14 秒 | 按住期間換指、手滑短暫放開，只要在這時間內按回來就不算斷 |

也就是說：**只有「提早很多放開」才會 MISS**，而那個 MISS 會凍結當下的光柱長度再淡出，
不會讓整條光柱瞬間消失。係數在 `game/Playfield.gd` 開頭：

```gdscript
const HOLD_GRACE_MIN := 0.18
const HOLD_GRACE_MAX := 0.40
const HOLD_GRACE_RATIO := 0.18
const HOLD_REPRESS_BUFFER := 0.14
```

### 4-4 畫面特效

除了移動視窗，譜面也可以直接對「畫面本身」動手。特效加在
「舞台貼圖 → 視窗」的合成 shader 上，所以**分割視窗時每一塊都會同步**。

| type | 名稱 | 說明 |
|---|---|---|
| `flash` | 白色閃光 | 整片刷白再快速退掉（適合重拍） |
| `glitch` | 故障 | 水平條塊隨機位移 + RGB 分離 |
| `invert` | 反色 | 黑變白、白變黑 |
| `blur` | 模糊 | 五點取樣模糊，適合「失神」的段落 |
| `chroma` | 色散 | 紅藍分離，邊緣出現色邊 |
| `scanline` | 掃描線 | CRT 掃描線 + 緩慢滾動 |
| `vignette` | 暗角 | 四周往內收暗 |
| `shake` | 畫面震動 | 畫面抖動（不是視窗抖動） |
| `zoom` | 鏡頭縮放 | 以畫面中心放大／縮小 |

每個事件：`{ "beat", "type", "duration", "strength" }`。
`strength` 是 0–1 的相對強度（`zoom` 例外，是放大比例）。

同一種特效同時觸發時**取最大值而不是相加**，所以連續放兩個白閃不會變成全白。
事件時間點以「拍」儲存，跟音符一樣會跟著 BPM 變化跑。

係數在 `game/EffectDirector.gd` 的 `KIND_DEFAULTS`（每種特效的預設長度、
進出速度）與 `game/WindowDirector.gd` 的 `CROP_SHADER`（實際畫面處理）。

**`attack` 是「佔總長度的比例」，不是秒。** 它決定特效淡入要花多久：

```
強度 = min(進度 / attack, (1 - 進度) / release)
```

這裡有個容易搞錯的地方：**譜面標記的那一拍是「最強」的瞬間，不是淡入的起點。**
實際播放時，事件會提前 `attack × duration` 秒開始（`EffectDirector._event_start()`）：

```
暗角   duration 0.9s、attack 0.20 → 提前 0.18s 開始淡入，第 36 拍剛好全黑
反色   duration 0.3s、attack 0.25 → 提前 0.075s 開始淡入
閃光   duration 0.35s、attack 0.02 → 提前 0.007s，幾乎看不出來（閃光本來就該是硬切）
```

**反色的 `attack` 原本是 `0.04`**（0.3 秒的特效只淡入 12ms，比一幀還短），
實測就是「一幀切換」——第 553 幀亮度 9、第 554 幀 215，完全沒有漸變感。
現在拉到 `0.25`（約 4–10 幀，看事件長度），淡入才真的看得出來。
`attack × duration` 不到 30ms 的效果在 60fps 下基本等於硬切，調參數時可以拿這個當下限。

所以「我標在第 36 拍」就真的會在第 36 拍看到滿強度的暗角，而前面 0.18 秒是柔和的淡入。
時間軸上那個橘色標記下方的細線就是淡入區間，標記本身才是峰值。

如果當初不提前、直接從標記點才開始淡入，暗角要 163ms 才到九成，
看起來就會像「特效比譜面慢半拍」——這也是為什麼要提前，而不是把 `attack` 調小
（調小雖然對齊了，但會讓需要柔和進場的特效變得很硬）。

想調整個別特效的手感就改 `attack`（越大越柔、提前越多）；`release` 控制淡出。

> **想直接看效果**：選曲列表裡的「**特效示範**」是一張 12 秒、16 顆音符的譜，
> 依序放完閃光→故障→反色→掃描線→色散→模糊→暗角七種特效。
> 它只是給你看的，不需要就整份刪掉（`assets/charts/特效示範.json`）。

### 4-5 結算與評分

**什麼時候進結算畫面？**

歌曲結束與譜面內容結束，取**先發生的那一個**再加 3 秒：

| 情況 | 進結算的時間 |
|---|---|
| 歌曲先結束 | 音檔播完 + 3 秒 |
| 譜面先結束 | 最後一顆音符／特效／軌道／視窗事件結束 + 3 秒 |

「譜面內容結束」包含：最後一顆音符的尾端、最後一個軌道關鍵影格、最後一個
視窗事件（含動畫長度）、最後一個特效（含持續時間）。取先結束的那一個是為了
避免「音檔尾巴很長、譜面早就打完」時要空等好幾分鐘。

音樂在進結算時會淡出 0.9 秒，不會「啪」一聲斷掉。

**分數（滿分 1,000,000）**

```
總分 = 判定分 900,000 + 連擊分 100,000
判定分 = 900,000 ×（Σ 音符權重 ÷ 音符總數）
連擊分 = 100,000 ×（最大連擊 ÷ 音符總數）
```

每個音符的權重上限是 1.0：

| 判定 | 權重 |
|---|---|
| PERFECT（±45ms） | 1.0 |
| GREAT（±85ms） | 0.8 |
| GOOD（±135ms） | 0.4 |
| MISS | 0 |

長條比較特別：**頭部佔 70%、尾端佔 30%**。頭部打中只先拿到
`0.7 × 判定權重`，要完整接到尾端才補上剩下的 0.3；中途放開整顆變 MISS。

所以「全部 PERFECT + 所有長條都接到尾端 + 不斷 combo」剛好是 **1,000,000**。

**評價（由好到差，結算畫面照這個順序由上往下排）**

| 評價 | 分數門檻 |
|---|---|
| SS | 1,000,000（全 PERFECT） |
| S | 950,000 |
| A | 880,000 |
| B | 800,000 |
| C | 650,000 |
| D | 未滿 650,000 |

結算畫面會把六個評價由上往下列出來，**你拿到的那一個會亮起來**，其餘壓暗，
一眼就能看出還差多少分。

## 5. 譜面編輯器

打開 `tools/chart_editor.html`（直接雙擊，不需要伺服器、不需要安裝）。

### 流程

1. **載入音樂** — 選 mp3 / ogg / wav。
2. **分析 BPM** — 會做頻譜通量 + 梳狀濾波，列出幾個候選 BPM 與 offset，點一下就套用。
   （也可以手動輸入或用 Tap Tempo。）
3. **畫音符** — 左鍵新增、拖曳變長按、右鍵刪除、拖曳音符移動。
4. **做隊形** — 在右邊的「隊形預覽」拖曳軌道，按「在目前拍新增關鍵影格」。
5. **譜面設置** — 右上角 `⚙`（或 `Ctrl+,`）決定這首歌的長相：音符樣式、大小、無邊框、全螢幕、
   初始視窗大小／位置，以及背景圖與壓暗程度。背景預覽會依初始視窗比例顯示，並可勾選
   「顯示音符安全區」疊上四軌與判定線；兩側欄位可以用頁首的 `◧` / `◨`（或 `Alt+1` / `Alt+2`）收合，
   收合狀態會記在瀏覽器裡。
6. **加視窗事件 / 特效事件** — 選類型、填參數、按新增。時間軸右側的紫色視窗事件標記可以直接
   上下拖曳調整拍數，右鍵刪除。
7. **檢查後匯出** — 按「檢查譜面」（`Ctrl+Shift+S`）或直接匯出；有錯誤（同拍同軌重複、超出音樂長度、
   事件重疊…）會先跳清單並阻止匯出，可選擇「仍要匯出」。匯出的 JSON 存到 `assets/charts/`，遊戲就抓得到。

不確定音符要放在哪一拍的話，先按「分析目前音樂」，把鼓點與旋律畫出來再對。

### 吸附（1/1 ～ 1/256、無限制）

底部工具列的「吸附」決定音符會貼到哪個格線：

| 選項 | 用途 |
|---|---|
| 1/1 ～ 1/8 | 一般節奏 |
| **1/12 / 1/24** | 三連音、六連音 |
| **1/16 / 1/32** | 細碎的裝飾音 |
| **1/256** | 幾乎等於自由放置，但還是會貼到極細的格線 |
| **無限制** | 完全不吸附，音符落在滑鼠的實際位置（小數 4 位） |

拍線只畫到看得見的密度為止（放大到 `pxPerBeat × step > 7` 才畫細分線），
所以選 1/256 不會讓畫面變成一條條灰線。

### 播放倍速（采音用）

底部工具列的「速度」：`0.25× / 0.5× / 0.75× / 1× / 1.25× / 1.5× / 2×`，
`[` / `]` 可以一階一階調（播到一半也能調，會從目前位置接續，不會跳拍）。

慢速主要是給**采音**用的：複雜的鼓點或三連音在 1× 常常一閃就過去了，
降到 0.5× 或 0.25× 就聽得出每一顆的位置。譜面資料本身不受影響——
存的一律是「拍」，播放速度純粹是編輯器的試聽工具。

* 波形、播放頭、音符捲動全部會跟著變慢（時間換算統一走 `songTime()`）。
* 倍速會記在 `localStorage`，下次開啟沿用。
* **變速會一起改變音高**（跟錄音帶一樣）：Web Audio 的 `playbackRate`
  沒有內建的「變速不變調」，所以 0.5× 會低一個八度。抓節奏沒差，
  但要判斷絕對音高時記得切回 1×。

### 復原 / 重做

工具列左上的 `↶ 復原` / `↷ 重做`，或 `Ctrl+Z` / `Ctrl+Shift+Z`（`Ctrl+Y` 也可以）。

做法是**整份狀態的快照**（音符 + 關鍵影格 + 視窗事件 + 設定），
不是逐動作反向操作——一個拖曳可能同時改到好幾個陣列，逐動作反向很容易只還原一半。
一次拖曳 = 一步（放開滑鼠時才記錄），打字則是在離開欄位時才記一步，
不然復原會變成「退一個字」。上限 60 步。

### 譜面設置（寫進 JSON 的 `settings`）

| 欄位 | 說明 |
|---|---|
| 音符樣式 | `不限` = 依玩家設定；`只能長條` / `只能圓球` = 這個譜面鎖定樣式 |
| 音符大小 | 0.4–2.5 倍，會再乘上玩家的設定 |
| 預設無邊框 | 進場時直接使用無邊框視窗（預設開） |
| 全螢幕 | `允許` = 照玩家的全螢幕設定；`不允許` = 進場強制視窗模式（離開後還原） |
| 初始視窗大小 / 位置 | 寬高填 0 = 沿用玩家目前大小；可勾「開場自動置中」或指定 X / Y |
| 背景圖 | 選一張圖（路徑寫進 `settings.background`）＋「背景壓暗」滑桿 |
| 背景安全區預覽 | 依初始視窗比例顯示背景，可勾選疊上四軌與判定線（只影響預覽，不寫進譜面） |
| 目前隊形 → 初始位置 | 把預覽上的四條軌寫成第 0 拍的關鍵影格 |
| 清除初始位置 | 刪掉第 0 拍的那四個關鍵影格 |

初始位置刻意用「第 0 拍的關鍵影格」實作，而不是新增一個格式欄位——
遊戲端完全不用多寫程式，插值、緩動、編輯全部沿用既有機制。

### 特效事件

右欄（往下捲）「特效事件」選類型 → 填持續拍數與強度 → 「在目前拍新增」。
支援九種：白色閃光、故障、反色、模糊、色散、掃描線、暗角、畫面震動、鏡頭縮放。
時間軸左側會出現橘色 `F` 標記，跟視窗事件（右側紫色）分開；視窗事件的紫色標記可直接拖曳改拍數。

`resize` 事件的「縮放錨點」決定哪個角固定不動。預設 `center` 是中心對稱（左右、上下同時伸縮）；
選 `topleft` 就只會往右下長大 / 往右下縮小，適合做「畫面往一邊滑開」的效果。

#### 特效預覽（在中間譜面上直接看）

「特效事件」最上面有一顆 **`▶ 套用特效預覽`**。打開後，中間那塊譜面會跟著播放頭
套用當下正在生效的特效——不用進遊戲就能調參數。

| 情況 | 顯示 |
|---|---|
| 播放中 | 依 `attack / release` 包絡即時變化，跟遊戲一致（會比標記點早一點開始淡入） |
| 暫停時 | 照實際包絡顯示：停在**標記上**就是 100%，停在淡入段就是中間值（狀態列會寫幾 %） |
| 播放頭不在任何特效內 | 譜面保持原樣，狀態列寫「這個位置沒有特效」 |
| 按鈕下方 | 即時顯示「預覽中：故障 82%、色散 40%」 |

時間軸上橘色 `F` 標記下方那條細線是**淡入區間**：線的末端（標記）才是全強度，
線的另一頭是開始淡入的位置。長度 = `attack × 持續拍數`，所以暗角會比閃光長很多。

* 開關狀態會記在 `localStorage`，重新整理後保持。
* 點右邊清單裡的特效可以直接跳到那一拍，配合預覽就是「點一下 → 看效果」。
* 只影響**中間的譜面**，左右側欄與時間軸標記不受影響，所以還是可以一邊看一邊編輯。
* 想專心編輯就再按一次關掉（`■ 關閉特效預覽`）。

實作方式：編輯器沒有 shader，所以是「整張 canvas 快照 → 重畫（縮放／震動／
`ctx.filter` 反色與模糊／水平條塊／RGB 三通道位移）→ 疊加（閃光／掃描線／暗角）」。
係數刻意對齊 `WindowDirector.CROP_SHADER`，看起來會接近實際遊玩；
唯一的差異是 CSS 的 `blur()` 是高斯模糊、比 shader 的五點取樣強，所以半徑壓到 `3.5` 倍。

### 時間單位（拍 / 秒）

編輯器裡**所有位置與長度都用「拍」**：音符、關鍵影格、視窗／特效事件的時間，
以及視窗動畫長度、特效持續拍數。只有兩個地方還是秒：

| 欄位 | 為什麼是秒 |
|---|---|
| `Offset` | 「第 0 拍在音檔中的第幾秒」，本質是音訊位置 |
| 音檔長度 / BPM 分析結果 | 直接來自音訊檔 |

匯出的 JSON 仍然照遊戲格式把 `duration` 寫成**秒**：長度在編輯器裡以拍儲存，
匯出（以及每 4 秒一次的自動草稿）時才換算；舊譜面載入時再換算回拍。
所以改 BPM 之後，事件的拍長度會跟音符一樣留在原本的小節位置，不會變成半拍。

頁首的「小節」與關鍵影格詳細資料的「位置（小節:拍）」是 `4/4` 的顯示輔助
（譜面格式沒有拍號資訊），實際資料仍然只有拍數。

### 采音輔助（鼓點 / 旋律）

右欄最下方「采音輔助」→ 勾選要看的標記 → 按「分析目前音樂」，
編輯器會直接在瀏覽器裡對音檔做 STFT，畫出兩種參考線：

| 標記 | 顏色 | 判斷方式 |
|---|---|---|
| 鼓點 | 橘色虛線 | 低頻（<160Hz，大鼓）與高頻（2k–8kHz，小鼓／鈸）的頻譜通量突起 |
| 旋律 | 青色虛線 | 中頻（160–2000Hz）的頻譜通量突起，再補上「音高改變」的位置 |

* 兩種可以分開開關，畫在音符**下面**，不會擋住編輯。
* **靈敏度滑桿**是「顯示時才過濾」，拖動不需要重新分析：往左只留最強的，
  往右連細碎的裝飾音都會出現。
* 分析結果只存在記憶體，換音樂會自動清空；重開編輯器要重新按一次。
* 標記只是「可能的位置」，實際還是以你聽到的為準——它的用途是幫你快速對拍，
  不是自動產譜。

### 關鍵影格怎麼看完整資訊

軌道右側的**菱形標記**就是關鍵影格：

| 操作 | 效果 |
|---|---|
| **懸停** | 浮出完整數值：拍、小節、X、Y、旋轉、縮放、緩動、與前後格的間隔 |
| **雙擊** | 開啟詳細資料視窗，八個欄位全部可以直接改（改完按「套用」） |
| **右鍵** | 選單：編輯詳細資料 / 複製到播放位置 / 跳到這一拍 / 刪除 |

右邊的「軌道關鍵影格」清單也一樣：懸停看那一拍**四條軌**的完整數值，雙擊編輯。

### 隊形編輯（拖曳 / 微調 / 放大）

| 操作 | 效果 |
|---|---|
| 拖曳軌道 | 左右移動（`x`） |
| `Shift` + 拖曳 | 旋轉（`rot`，±45°） |
| `Alt` + 拖曳 | 縮放（`scale`，0.4–1.8） |
| 點一下軌道 | 選取，下方會出現 X / 旋轉 / 縮放 / **透明度** 的控制項 |
| 方向鍵（已選取軌道時） | ← → 移動 0.01、↑ ↓ 旋轉 1°；按住 `Shift` 加速 |
| 點空白處 | 取消選取（方向鍵恢復成移動播放位置） |
| **放大編輯** | 把預覽畫布放大到整個視窗（`Esc` 或「完成」返回） |
| **重置隊形** | 四軌回到 `x=0, rot=0, scale=1, alpha=1`（再按「新增關鍵影格」寫入） |
| **清空所有關鍵影格** | 清掉整份譜面的隊形（會先詢問） |

**單軌透明度**是每一條軌道自己的屬性（`alpha`，0–100%），不是整張譜面的設定：
選取某條軌後拉滑桿，那一條的底色、判定球、**以及這一軌掉下來的音符**會一起變淡。
它跟 `x` / `rot` / `scale` 一樣寫進關鍵影格，所以可以做「第 32 拍開始第 4 軌淡出」這種效果。
選取中的那條在預覽裡至少保留 45% 亮度，拉到 0 也還點得到。

主捲軸（時間軸）刻意不套用透明度——那裡是對拍用的工作區，
把某一軌調暗會讓音符看不見，等於沒辦法編輯；要看實際長相請看隊形預覽。

**靈敏度**滑桿預設 `0.35×`——舊版固定 `1.0`，滑鼠拉 10 像素軌道就跑掉 10 像素，
很難放到想要的位置。現在拖曳是「以按下瞬間的值為基準」做增量，
不會把每一次 mousemove 的小誤差累積起來，放開時位置跟手是對的。
真的要精準到小數第二位，就用數值欄位或方向鍵。

放大編輯不是另開瀏覽器視窗，而是把同一塊 canvas 搬進全螢幕覆蓋層：
這樣拖曳邏輯、選取狀態、數值欄位都只有一份，不會有兩邊不同步的問題。

### 快捷鍵

| 鍵 | 功能 |
|---|---|
| `空白` | 播放 / 暫停 |
| `1`–`4` | 在目前拍、對應軌道放一個音符 |
| `Delete` | 刪除選取音符 |
| `Ctrl+Z` | 復原 |
| `Ctrl+Shift+Z` / `Ctrl+Y` | 重做 |
| `Ctrl+S` | 匯出（先驗證，有錯誤會阻止） |
| `Ctrl+Shift+S` | 檢查譜面（不匯出） |
| `Ctrl+,` | 開啟 / 關閉「譜面設置」 |
| `[` / `]` | 播放速度慢一階 / 快一階 |
| `Alt+1` / `Alt+2` | 收合左 / 右側欄 |
| `Esc` | 關閉檢查結果 / 詳細資料視窗 / 右鍵選單 / 放大編輯 / 譜面設置 |
| 方向鍵 | 移動播放位置（有選取軌道時改成微調隊形） |
| 滾輪 | 捲動畫面（`Shift` + 滾輪 = 縮放） |

編輯器每 4 秒會自動存一份草稿到瀏覽器的 localStorage，
按上方「還原草稿」可以救回來。

## 6. 譜面格式

```json
{
  "format": "reverb-chart",
  "version": 1,
  "meta": {
    "title": "Untitled (Demo)",
    "artist": "local",
    "difficulty": "Normal",
    "level": 8,
    "audio": "res://assets/audio/my_song.mp3"
  },
  "timing": {
    "offset": 0.375,
    "bpm_segments": [{ "beat": 0, "bpm": 120 }]
  },
  "settings": {
    "note_style": "any",
    "note_scale": 1.0,
    "borderless": true,
    "fullscreen": "allow",
    "background": "res://assets/backgrounds/bg.jpg",
    "background_dim": 0.45,
    "window": { "width": 1280, "height": 720, "x": 0, "y": 0, "centered": true }
  },
  "notes":   [{ "beat": 8.0, "lane": 0, "len": 0.0 }],
  "lanes":   [{ "beat": 32, "lane": 0, "x": -0.55, "rot": -7, "scale": 1.0,
                "alpha": 0.6, "ease": "smooth" }],
  "windows": [{ "beat": 44, "type": "split", "axis": "vertical", "move": "mirror" }],
  "effects": [{ "beat": 48, "type": "flash", "duration": 0.35, "strength": 1.0 }]
}
```

* **音符用「拍」儲存，不是秒。** 改 BPM 或做 BPM 變化時，音符會自動跟著跑。
* `offset`：第 0 拍在音檔中的秒數（前奏長度）。音檔前面有空白就調大。
* `bpm_segments`：支援多段 BPM，段落之間以拍數銜接。
* `len`：長按長度（拍）。`0` = 單點。
* `lanes` 的 `x` / `y` 單位是軌道寬度，不是像素。
* `lanes` 的 `alpha` 是**單軌透明度**（0.0–1.0，省略 = 1.0），會跟 `x` / `rot` / `scale` 一樣在關鍵影格之間插值；
  這一軌的底色、判定球與音符都乘上它。
* `settings` 整段可以省略，省略時等於上面那組預設值：
  * `note_style`：`any` / `bar` / `orb`。不是 `any` 時會蓋掉玩家的樣式設定。
  * `note_scale`：0.4–2.5，會乘上玩家的音符大小設定。
  * `borderless`：進場是否用無邊框視窗。
  * `fullscreen`：`allow` / `block`。`block` 進場會強制切成視窗模式。
  * `background`：背景圖路徑（`res://assets/backgrounds/...`、`user://...` 或絕對路徑）。
    空字串 / 省略 = 純黑。只存路徑，圖片本身不進 JSON。
  * `background_dim`：背景上方黑幕的強度 0–1（預設 0.45）。越高越暗、音符越好讀。
  * `window`：進場時套用一次的初始視窗。`width` / `height` 任一為 0 = 沿用玩家目前的大小；
    `centered: true` 會置中並忽略 `x` / `y`；`false` 時放在 `x`, `y`（螢幕像素）。
    只在**每首譜面第一次開始**套用，暫停恢復不會再把視窗拉回去。

`windows` 的事件型別：`move` / `resize` / `recenter` / `shake` / `split` / `merge` /
`ontop` / `borderless`。（舊譜面的 `fullscreen` 事件會被忽略。）
`resize` 可加 `anchor`: `center`（預設）/ `topleft` / `topright` / `bottomleft` / `bottomright`，
指定縮放時固定不動的角落。
`split` 固定分成兩塊，可加 `axis`: `vertical`（預設，左右）/ `horizontal`（上下），
以及 `move`: `mirror`（預設，以中線對稱）/ `same`（同方向）。
舊譜面的 `count` 會被忽略（以前可以分 2–3 塊，現在一律 2 塊）。

`effects` 的事件型別：`flash` / `glitch` / `invert` / `blur` / `chroma` / `scanline` /
`vignette` / `shake` / `zoom`，每個都有 `duration`（秒；編輯器以拍輸入，匯出時換算）與
`strength`（0–1；`zoom` 是放大比例，0.08 = 放大 8%）。

### 從 osu!mania 轉譜

`tools/osu_to_chart.py` 可以把 4K mania 的 `.osu` 直接轉成上面的格式：

```bash
python tools/osu_to_chart.py "song.osu" \
  --audio "res://assets/audio/song.mp3" \
  --difficulty "LN Tech" --level 16 \
  --out "assets/charts/Message (osu).json"
```

轉換器處理的幾件事：

* 讀 `[TimingPoints]` 的 uninherited 段，建立「秒 → 拍」的分段映射，**支援中途換 BPM**。
* **自動挑 offset**：osu 的 timing point 常常沒有對在真正的重拍上（實測這張譜
  就差了 1/4 拍），直接拿它當第 0 拍，譜面在編輯器裡會全部卡在 `.75` 這種格線上。
  轉換器會試 ±1/2 拍共 17 個位移，取「量化誤差最小 → 落在整拍上的音符最多 → 位移最小」的那個。
* 把 hold（`type & 128`）的尾端時間換算成 `len`（拍）。
* 毫秒精度造成的 `15.9983` 這種數字，會在 3ms 內吸附到 1/2/3/4/6/8/12/16/24/32 分格。
* 同拍同軌的重複音符會捨去（遊戲裡會變成一顆永遠打不到的幽靈音符）。
* 難度等級預設用「2 秒窗內最大音符數」估算，可用 `--level` 覆蓋。

只支援 **4K**（本作只有四軌）；其他鍵數會直接報錯而不是硬轉。
轉完建議用 `--autohit --autoplay` 跑一次，`[AUTOTEST]` 應該要是 `score=1000000 acc=1.0000`。

```
  Main.gd                流程控制 + 全部 UI
  Chart.gd               譜面資料模型（JSON 讀寫、拍↔秒）

  AudioLoader.gd         音樂檔載入（含外部檔案）
  ImageLoader.gd         背景圖載入（res:// / user:// / 絕對路徑）與玩家自訂圖匯入

  fonts/NotoSansTC-Regular.otf

```

整個遊戲幾乎沒有 `.tscn`，畫面都是程式即時畫出來的。
好處是「所見即程式碼」，改數值不用開編輯器；壞處是不能用編輯器拉 UI。
如果你想要混合式（部分場景用編輯器做），把 `Playfield` 換成一個 `Node2D` 場景即可。

## 8. 程式架構（想改的話從這裡下手）

### 時間是怎麼算的

`Conductor.gd`：

```gdscript
實際時間 = 播放位置 + 距離上次混音的時間 - 輸出延遲
```

直接拿 `get_playback_position()` 判定會有 10–30ms 的鋸齒，所以要補這兩項。
另外有 2.6 秒的 `preroll`（預捲），這段時間 `song_time` 是負的，音符會先掉下來。

### 判定

`Playfield.gd` 的 `_try_hit()`：

| 判定 | 誤差 |
|---|---|
| PERFECT | ±45 ms |
| GREAT | ±85 ms |
| GOOD | ±135 ms |
| MISS | 超過 180 ms |

想調難度就改這四個常數。

長條（Hold）的頭部用同一套判定，但尾端另外有一套放寬規則（見 4-3），
而且長條是**獨立追蹤**的：`_active_holds` 存的是「正在按住 / 正在淡出」的音符索引，
不是用時間視窗回頭掃描。這一點很重要——用時間視窗掃的話，
按住超過視窗長度之後那顆音符就再也掃不到，光柱會突然消失、判定也永遠不會完成。

### 音符為什麼不是節點

所有音符都只是一筆資料，整個畫面在**一次 `_draw()`** 裡畫完。
好處是幾百顆音符也不會有節點管理的開銷，而且軌道變換只要換一個 `Transform2D`。

### 想加新特效

**先分清楚兩種「特效」**，加錯地方會完全沒反應：

| 種類 | 範圍 | 加在哪 |
|---|---|---|
| 打擊回饋 | 只有單一顆音符／單一軌 | `Playfield` |
| 全畫面特效 | 整個遊戲畫面 | `EffectDirector` + `WindowDirector.CROP_SHADER` |

打擊回饋：

* 打擊粒子：`Playfield._build_particles()`（每一軌 12 顆 `CPUParticles2D` 環狀輪替，貼圖是程式產生的）。
  舊版每軌只有一顆、每次擊中都 `restart()` 同一顆，連打時會把上一顆的粒子整批清掉；
  改成輪替池（優先挑已跑完的發射器）之後，每次擊中都有獨立的粒子，1.4 秒的生命會完整跑完。
* 擴散光波：`_spawn_ring()` / `_draw_rings()`。
* 軌道晃動：`_shake`（只有那一軌，不是整個畫面）。

全畫面特效要動三個地方，缺一不可：

1. `game/EffectDirector.gd` 的 `KIND_DEFAULTS` 加一項（預設 `duration` / `strength` / 進出速度）。
2. `game/WindowDirector.gd` 的 `CROP_SHADER` 加一段處理，讀一個新的 `uniform float fx_xxx`。
3. `EffectDirector._process()` 的 `set_effect_params({...})` 把累積值傳出去。

```gdscript
# 1. EffectDirector.gd
const KIND_DEFAULTS := {
    ...
    "my_fx": {"duration": 0.5, "strength": 1.0, "attack": 0.05, "release": 0.5},
}

# 3. EffectDirector._process()
_director.set_effect_params({
    ...
    "fx_my_fx": float(acc.get("my_fx", 0.0)),
})
```

```glsl
// 2. WindowDirector.gd — CROP_SHADER
uniform float fx_my_fx = 0.0;   // 跟其他 fx_ 一樣用 0–1

// 在 frag() 取樣時用 fx_sample(suv)，它會自動處理分割視窗的裁切
vec3 col = fx_sample(suv);
col = mix(col, vec3(1.0, 0.0, 1.0), fx_my_fx * 0.5);   // 範例：整片染洋紅
```

> **不要把特效寫成 `SubViewport` 底下的 `Control`。**
> 遊戲畫面是在 `SubViewport` 裡畫的，主視窗只是一塊 `ColorRect` 去取樣那張貼圖；
> `SubViewport` 裡新增的 `Control` 節點**不會被繪製**，會出現「節點存在、程式有跑、
> 但畫面上什麼都沒有」的狀況。所有全畫面效果都必須經過合成 shader。

`fx_sample(suv)` 的參數是**畫面座標**（0–1，指整個視窗），
它內部會用 `uv_offset` / `uv_scale` 換算成舞台座標，所以分割視窗下每塊都對得上；
直接 `texture(view_tex, suv)` 在分割模式下會取樣錯位置。

震動類特效不要動 `Playfield.position`——那只會晃到舞台，
視窗本身（含邊框與分割線）不會動。要「整個視窗在抖」請用 `fx_shake`，
它是在 shader 裡位移取樣座標。

### 想改視覺

畫面上所有東西都是 `_draw()` 裡用程式畫出來的，沒有外部圖檔：

| 想改的東西 | 去哪裡找 |
|---|---|
| 光球的長相 | `_draw_orb()`（圓球音符與判定球共用）、`_make_orb_texture()` |
| 長條音符的長相 | `_draw_bar_note()`、`_draw_capsule()`、`_layout()` 的 `note_bar_w` / `note_bar_h` |
| 長按光柱 | `_draw_hold_body()`、`_make_beam_texture()`（橫向漸層） |
| 判定球的尺寸／亮度 | `_draw_receiver()`、`_layout()` 的 `rec_r` |
| 音符光球大小 | `_layout()` 的 `note_r` |
| 柔光貼圖 | `_make_glow_texture()`（徑向漸層，白色） |
| 背景 | `_draw_background()`（背景圖 cover + 黑幕，再疊拍線與底部光池）、`set_background()` |
| 四軌是否分色 | `LANE_COLORS` 陣列（現在四格都是 `Color(1,1,1)`） |

## 9. 開發用指令

```bash
# 直接開始上次玩的譜面
godot --path . -- --autoplay

# 自動完美打擊（驗證判定與計分）
godot --path . -- --autoplay --autohit

# 指定譜面（路徑含空格也可以，記得用引號）
godot --path . -- --chart="res://assets/charts/Message (osu).json" --autohit --autoplay

# 直接跳到某個畫面（改 UI 時很方便）：menu / select / settings
godot --path . -- --screen=settings

# 臨時切換音符樣式（不寫入設定檔）：bar / orb
godot --path . -- --autoplay --note=orb

# osu!mania 4K → 本作譜面
python tools/osu_to_chart.py song.osu --audio "res://assets/audio/song.mp3"
```

### 不用開視窗也能驗證判定

`--autohit` 會在音符進入判定視窗時自動按下，跑完後把成績印到 console。
搭配 `--headless` 就能當成回歸測試：只要有漏判，`MISS` 就不是 0。

```bash
# 完整跑一首（3000 幀 ≈ 50 秒，含 2.6 秒預捲；長歌要自己加大 --quit-after）
godot --headless --path . --fixed-fps 60 --quit-after 3000 -- --autoplay --autohit
# 輸出範例（野花香，195 顆）：[AUTOTEST] grade=SS score=1000000 acc=1.0000 max_combo=195 P=195 G=0 D=0 M=0
# 轉換後的 osu 譜（MEGALOVANIA，389 顆）：
#   [AUTOTEST] grade=SS score=1000000 acc=1.0000 max_combo=389 P=389 G=0 D=0 M=0
# 長譜（Message，932 顆，約 3 分鐘，要 --quit-after 16000）：
#   [AUTOTEST] grade=SS score=1000000 acc=1.0000 max_combo=932 P=932 G=0 D=0 M=0
```

`--autohit` 全部 PERFECT 時分數一定是 `1000000`（判定分 900,000 + 連擊分 100,000）。
換句話說：**只要 `score` 不是 1,000,000，就代表有地方漏判或多算**——
這比看 `acc` 更直覺，因為 `acc` 只反映判定、看不到連擊。

音符數量取決於載入的譜面（`_default_chart()` 會拿上次玩的譜面，
沒有紀錄時才用 `assets/charts/` 排序後的第一張），
所以 `P` 的數字會跟著換；重點是 `M=0`、`acc=1.0000`。
換幀率再跑一次應該得到**完全相同**的分數——判定只看歌曲時間，不看幀數：

```bash
for fps in 144 60 30 20 15; do
  godot --headless --path . --fixed-fps $fps --quit-after $((fps*50)) -- --autoplay --autohit
done
```

> 結束時如果看到 `ERROR: 1 resources still in use at exit`（AudioStreamMP3）不用緊張：
> 那是 Godot 引擎在「音訊還在播放時被直接關掉」的已知問題
> （[godotengine/godot#76745](https://github.com/godotengine/godot/issues/76745)），
> 只出現在命令列直接執行時，不影響遊玩與判定。

### 離屏錄影（不開視窗也能看畫面）

```bash
godot --path . --resolution 1280x720 --write-movie out.avi --fixed-fps 30 --quit-after 1200 -- --autoplay --autohit
ffmpeg -ss 11 -i out.avi -frames:v 1 frame.png
```

注意：錄影模式**無法真的改變視窗大小**，所以譜面裡的 `resize` 事件在錄影中
會看起來像「畫面被放大」（遊戲內 viewport 縮小了，但錄影解析度沒變）。
真實視窗下是正常的，錄影時避開那幾拍就好。

## 10. 已知限制 / 下一步

* **多視窗**需要作業系統允許建立子視窗；少數環境（遠端桌面、某些視窗管理器）可能失效。
  失效時遊戲本身仍可玩，按 `Esc` 會還原。
* 分割視窗的縮放是**等比例縮放同一塊裁切畫面**（放大 = 看得更少但更大），
  不是「看到更多遊戲畫面」。要看到更多內容得改 shader 的 `uv_scale`，
  但那樣兩塊視窗的內容會重疊。
* 分割時 `move: "mirror"` 會讓兩塊**靠近或分開**，但每一塊顯示的內容仍然是
  固定的那一半（左半永遠是左半），不會跟著視窗位置跑。這是刻意的：
  內容跟著跑的話，兩塊分開時中間會出現一片空白。
* **匯出成執行檔**時，`assets/charts/*.json` 要記得加進匯出篩選條件
  （專案 → 匯出 → 資源 → 篩選 `*.json`），否則選曲列表會是空的。
* 目前沒有：打擊音效、成績上傳、Replay、手把支援、變速（BPM 變化已在格式支援，但示範譜面沒用到）。
* **采音輔助只是參考線**：它偵測的是音訊裡的實際能量突起，不會對齊 BPM 網格
  （實測約一半的鼓點會剛好落在格上，其餘是切分音或裝飾音）。
  想要精準的譜面還是得自己聽＋用 1/16 吸附微調。
* **全螢幕與「視窗玩法」是互斥的**：全螢幕下沒有可移動／縮放的視窗，
  譜面的 `move` / `resize` / `split` 事件會看起來沒反應。
  全螢幕**不再是譜面事件**（舊版有 `fullscreen` 事件，已移除，舊譜面會被自動忽略），
  現在只剩兩件事：玩家的全域設定（設定 → 全螢幕），以及譜面層級的
  `settings.fullscreen` 政策——設成 `"block"` 時，載入這張譜會強制退回視窗模式，
  離開時再還原。譜面若很依賴視窗玩法就設 `block`。
* **無邊框模式**（預設）只是把視窗標題列拿掉，仍然是一個可拖曳的視窗，
  跟全螢幕不衝突。
* 想要「多軌 + 對手」的話，可以擴充 `Chart` 的 note 欄位（例如加 `side`），
  再讓 `Playfield` 分兩組繪製。
